# Development history

## 2026-10-16 — Discovery-call inquiry email notifications

The discovery-call form previously saved inquiries to Neon but did not notify the site owner. The inquiry route now sends a plain-text notification through the Resend integration already configured on the Vercel project, after the database insert succeeds. It reads the existing server-side `Messaging_RESEND_API_KEY` and `Messaging_RESEND_EMAIL_DOMAIN` values, sends to the site footer contact address (`marcus@leagueofledgers.com`) by default, and allows the recipient to be overridden with `INQUIRY_NOTIFICATION_EMAIL`. The notification includes the submitter’s name, work email, message, and inquiry ID, and uses an idempotency key based on that database ID.

Notification errors are handled separately from the Neon insert: the inquiry remains saved and the form still receives a successful response, while Vercel logs record whether the mail request was skipped or rejected. The API response also includes a `notificationSent` flag for troubleshooting. No database schema change or additional package was needed. Standalone TypeScript checking and `git diff --check` passed. `npm run build` remained silent for about 30 seconds and was stopped, but commit `c18b3b3a82ecbe7400820af890b5207b7d67e544` was pushed to `origin/main` and Vercel reported its Production deployment `dpl_5RUT6PSQHn8cZTnMM4MMraGSeyv7` as `READY`, with `www.leagueofledgers.com` and `leagueofledgers.com` aliases. No real inquiry or test email was submitted. The sender uses an address on the Resend domain configured in Vercel, which must be verified in Resend for delivery.

## 2026-10-16 — Comprehensive website content and service-alignment revision

The published League of Ledgers site was audited against the intended U.S. bookkeeping positioning for HVAC, MEP, and home-service contractors. The earlier implementation had strong visual branding but mixed service names, package coverage, and add-on boundaries: job costing appeared broader than the tiers supported, existing field-service reconciliation was not clearly separated from new integration work, AP/AR and payroll language could imply more operational ownership than intended, and the page used a broad money-back guarantee, historical performance numbers, a client testimonial, and a dashboard presented as live without visible qualification.

This session preserved the existing layout, color system, logo, navigation, inquiry modal, calendar link, PostgreSQL inquiry route, package names, and base prices while replacing the content architecture. The six service cards now cover Monthly Bookkeeping & Financial Close; Accounts Payable & Receivable; Job Costing & Profitability Analysis; Balance Sheet Reconciliation & Asset Tracking; Field-Service Software Reconciliation; and 1099 Compliance & CPA Support. Each description now distinguishes standard bookkeeping from separately scoped transaction management, advanced reporting, setup, migration, filing, and approval responsibilities. The pricing comparison was expanded so the Apprentice ($600/month), Journeyman ($1,000/month), and Master ($1,650/month) tiers show consistent month-end close, statements, existing FSM reconciliation, AR/AP reconciliation, 1099 tracking, bookkeeper coverage, review cadence, and the different levels of job-costing and KPI reporting. Optional work now has six clearly scoped add-ons for AP/AR management, payroll reconciliation, cleanup, FSM setup/cleanup, advanced job costing, and 1099 preparation or filing support.

Unsupported or potentially misleading trust signals were revised rather than replaced with new unverified claims. The 90-day money-back guarantee, 100% audit-ready wording, and 20+ client statistic were removed. The hero now uses descriptive service language with a qualified 5–7 business-day close reference. The proof section is explicitly an illustrative League of Ledgers practice statement rather than a client testimonial, and the dashboard is labeled as illustrative data that is not a live client account. Primary calls to action are standardized to “Book a Free Discovery Call,” including the header, hero, plan actions, final CTA, and dialog heading. Typography overrides increase the readability of dense service, industry, pricing, add-on, dashboard, footer, and mobile copy while keeping the established visual hierarchy and responsive behavior.

The source was validated with `npm run build` on Next.js 16.3.4, including TypeScript checking, static page generation, and the dynamic inquiry route. Verified commit `2223a4f` was pushed to the linked repository, and the requested Vercel production URL now serves the revised copy; a cache-busting browser read confirmed the same content after the initial browser cache showed the prior version.

After the first production verification, a content-density review found that the asterisked “Included*” job-costing cells needed their qualifier immediately beside the comparison table. ## 2026-10-16 — Inquiry modal interaction and accessibility hardening

The inquiry modal was tightened so the booking flow behaves predictably during repeat visits and unreliable network conditions. The client component now centralizes modal open and close behavior, clears stale success and error state when a new inquiry begins, returns focus to the element that opened the dialog, closes on Escape, and exposes the navigation relationship through `aria-controls`. The form fields now have explicit labels and browser autocomplete hints, while the dialog supplies a title and description for assistive technology.

Submission handling was moved into a dedicated async handler with a sending guard, disabled submit control, `aria-busy` state, JSON error handling, and a connection-failure fallback. This prevents accidental duplicate inquiries and gives the visitor a usable recovery message when `/api/inquiries` cannot be reached. The disabled button styling was added to the shared stylesheet, and all modal-opening controls were made explicit `type="button"` controls so they cannot accidentally submit a surrounding form in future layout changes.

The existing PostgreSQL/`DATABASE_URL` inquiry route remains the system used by the page. The uncommitted Supabase dependencies that were already present in the working tree were not connected to the route because no Supabase environment variables, schema, migration, or approved backend switch is present; that decision keeps this change within the documented production contract. `npm run build` completed successfully on Next.js 16.3.4, TypeScript completed as part of the build, and `git diff --check` passed. Next.js also refreshed `next-env.d.ts` to reference the current `.next/types` output generated by the installed framework.
